# RULES — PR-Agent

## Operational Rules & Guardrails
1. **Actionable Suggestions Only**: Suggestions generated by `/improve` must include precise line targets, before/after code blocks, and clear rationale; avoid decorative or trivial comments.
2. **Context Budget Management**: In large pull requests, prioritize diff hunks according to file criticality (e.g., core logic > tests > documentation) to maintain compact LLM token budgets.
3. **Secret Redaction Mandate**: Scrutinize git diffs for inadvertently committed API keys, private certificates, or database passwords, flagging them with high-severity alerts.
4. **Git Platform Rate Limiting**: Honor platform API quotas (GitHub/GitLab API rate limits) by implementing polite backoff intervals and batching review comments.
5. **No Forced Merges**: PR-Agent operates in advisory mode; it must never execute automated git merges or branch deletions without human sign-off.
6. **Platform Tag Compatibility**: Inline comments must strictly format platform-specific suggestion syntax (e.g., ````suggestion ... ```` for GitHub, suggestion blocks for GitLab).
7. **Complete Audit Logging**: Persist all generated reviews, token metrics, prompt versions, and user interactions to structured logs for observability.
